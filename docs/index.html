🏢 Learn APIs the school way

How programs talk to each other, taught as the school's front office: a slip at the counter, a clerk, a stamped answer. Every lesson is a school story with a numbered diagram — and the counter is in the repo: a real HTTP/JSON API in ~235 lines of pure Python (zero dependencies) that you run, curl, break and extend.

🎒 Before lesson 01: you need Python 3 and curl — nothing else (no framework, no cloud). Helpful before: nothing; helpful after: the Database school (the record room behind this counter), the UI school (the notice board that calls it) and the AWS school's API Gateway lesson. What this is not: a framework tutorial — FastAPI, Express and Spring automate the four parts you read here; learn the parts first.

🔧 Two more showcase pages: every REST method — GET, HEAD, OPTIONS, POST, PUT, PATCH, DELETE drawn against the counter with the three words (safe, idempotent, cacheable) and a script that proves each rule; and every authentication method — Basic, API key, Bearer token, JWT, session cookie, OAuth 2.0 and its grant types, OpenID Connect, HMAC signing, mutual TLS, seven of them runnable against the same grades.
🔀 The showcase: this course builds one REST counter — every API type is the map of all the other shapes: REST, JSON-RPC, SOAP, GraphQL, gRPC, tRPC, OData, long polling, SSE, WebSocket, WebRTC, webhooks, queues, event streams, batch files, libraries, system calls and database drivers. Six of them run in this repo against the same five students, so you can compare the wire.
🗣️ Explain this out loud — after lesson 12: (1) Why does PUT get to be idempotent and POST doesn't — and what does an Idempotency-Key change? (2) A client got a 500. Should it retry? And a 400? (3) Offset vs cursor pagination: what goes wrong with page 7 when a row is inserted? (4) Which changes are safe to ship on /v1 and which force /v2? (5) 429 with Retry-After arrived — describe the client's next 10 seconds. (6) Where does an API gateway sit, and which three jobs does it take off your API?
